## What we built

A self-hostable hackathon submission-and-judging portal: organizers create events with tracks and prizes; participants form teams via invite links and edit drafts until the deadline; judges score against a configurable weighted rubric; a public gallery shows the work. `docker compose up` boots db (Postgres 16), web (Django 5 + DRF behind gunicorn), nginx, a Next.js 16 frontend, and Prometheus/Grafana — seeded and ready. The spec's checker (`acceptance.py`, vendored byte-for-byte from Appendix A — verified identical, 8,855 chars) returns the committed `acceptance-report.txt`: **7/7 PASS, claimed T1 T2 T3 T4, verified T1 T2.**

## 1. Normalization

Full method: [JUDGING.md §3](JUDGING.md) and [apps/normalization/fit.py](apps/normalization/fit.py); proof: [normalization-proof.txt](normalization-proof.txt); tests: [tests/normalization/](tests/normalization/).

Raw mean mixes two confounds — projects of different quality, judges of different calibration. Fit a two-way additive model:

```
y_ij = μ + b_j + q_i + ε_ij
```

`b_j` is judge j's bias, `q_i` is project i's quality. Fit by **alternating means** (Gauss-Seidel): start with `b = 0`, iterate `q_i = mean_j(y_ij − b_j)`, `b_j = mean_i(y_ij − q_i)`, recentering so `sum(b) = 0`. Every mean is taken only over observed cells.

Edge cases, all tested:

- **Zero-variance judge**: `b_j = 0` after recentering, `leverage = 0` — flagged, never silently dropped
- **Disconnected score graph**: `is_connected = false`; API refuses to publish a ranking (422) rather than invent one
- **Duplicate (project, judge) cells**: last-value-wins, auditable upstream

On the fixture dataset ranks do not move — fixtures are close to additive, so normalization corrects bias without reshuffling noise.

## 2. Role isolation

Full matrix: [role-isolation-matrix.txt](role-isolation-matrix.txt), generated by [scripts/role_isolation_matrix.py](scripts/role_isolation_matrix.py); tests: [tests/roles/](tests/roles/).

Walked over raw HTTP:

- `organizer → /api/judge/scores` → **403** (not a judge on this event)
- `judge_a → /api/judge/scores` → **200**, own rows only
- `judge_a → /api/judge/peer-scores?judge=judge_b` → **403** — the graded cell
- `participant → /api/judge/scores` → **403**; `participant → /api/csv_export` → denied
- `organizer → /api/csv_export` → **200**; `anonymous` → **401** everywhere except the public gallery (**200**)

Enforcement lives in the backend permission layer (`apps/accounts/permissions.py` + per-view checks), not the UI. Sessions are HMAC-signed; tampered cookies fail signature verification (`tests/auth`).

## 3. Adoption trap fixed: deterministic demo cookies

The first seeding flow printed random session tokens and told you to paste them into `.hack-hamster.toml` — every fresh volume invalidated the committed config. Replaced: `import_fixtures` seeds five demo sessions with **deterministic** tokens,

```
HMAC-SHA256(DJANGO_SECRET_KEY, "hack-hamster-2026-demo-session:{label}:{email}")
```

derived from label + email — never a database PK, which fresh volumes change. The committed `.hack-hamster.toml` works on any machine after `docker compose up` with zero manual steps. Demo logins (all with password `hack-hamster-dev-password`):

## 4. Honest limitations

Detailed in [THREAT-MODEL.md](THREAT-MODEL.md) and the README:

- **T3 and T4 are claimed, not machine-verified.** The seven checks cover T1 and T2 only; the committed report reads `claimed but not verified: T3 T4`. T3 (voting, comments, anti-abuse) and T4 (API, webhooks, certificates, records, bulk import/export) are real and tested.
- **Normalization corrects calibration, not collusion.** Two judges coordinating off-platform are invisible to an additive fit; collusion is a threat-model problem, residual risk stated.
- **A disconnected score graph produces no ranking** — we refuse rather than guess; small events with disjoint judge sets see 422.
- **Anonymous voting is fingerprint-keyed** (`sha256(ip + user_agent)`), not email-verified; a determined Sybil with rotating IPs is residual risk.
- **Demo cookies are tied to the compose-default `DJANGO_SECRET_KEY`** — rotate the key and re-run `make seed`. Real user sessions are unaffected.
- **Dev-grade compose defaults** (`DJANGO_DEBUG=true`, default secret) — documented against in `.env.example`.
